---
title: Turn rollback
description: Capture and review one turn's exact files before restoring their index and worktree boundaries.
---

Turn rollback captures staged and unstaged content separately in an exclusively
owned local Git workspace. It requires the provider's persisted binding ID.
Shared checkouts and unsupported platforms refuse; hooks do not infer ownership
or automatically capture files.

```sh
harn turn-rollback begin --binding <binding-id> --turn edit-one --generation 1 \
  --path src/example.ts new-file.txt
harn turn-rollback seal <capture-id> --binding <binding-id>
harn turn-rollback prepare <capture-id> --binding <binding-id> > proposal.json
harn turn-rollback apply --binding <binding-id> --plan proposal.json
harn turn-rollback apply --binding <binding-id> --plan proposal.json \
  --yes --actor reviewer --reason 'Undo this turn'
harn turn-rollback show <capture-id> --binding <binding-id>
```

Begin before editing and seal after the turn ends. Include every intended file,
including a planned new file, in `--path`. Parents must already exist. Prepare
prints a JSON proposal with the exact before and end index/worktree identities
for each path. Review that saved proposal. Apply previews it by default; an
actual restore requires `--yes`, actor and reason, a proven inactive workflow,
fresh content and exclusive ownership. A changed selected file, HEAD, binding,
turn generation or proposal refuses. Unselected files and their staged changes
remain outside the restore set.

Selected untracked files are captured only when explicitly named and not
ignored. Git and Harnery metadata, nested repositories, symlinks, hard links,
conflicts, intent-to-add entries, selected assume-unchanged/skip-worktree paths,
and split or sparse indexes refuse. Capture leaves the live index byte for
byte unchanged; restore retains unselected index flag semantics.

The limits are 100 selected paths, 8 MiB per snapshot, 64 captures and 64 MiB
captured bytes per binding. Index and worktree bytes both count. There is no
automatic eviction or rollback after a failed turn.

An interrupted apply reports `unknown` and refuses automatic retries. Its audit
and started record remain available for investigation, and an interrupted Git
index lock may remain. Do not remove a lock or repeat writes based only on
process death. A completed receipt is reported as `already_applied` only after
the restored content and current authority still match. This is a guarded
multi-file operation, without a crash-atomic transaction or a guarantee against
arbitrary external writers.

See [ADR 0216](/decisions/0216-turn-content-rollback/).
