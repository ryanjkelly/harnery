```
harn semantic <subcommand> [options]
```

`harn semantic` turns the bounded facts in an active Event Ledger V3 generation
into a broader read model for operator-facing surfaces. The generated meaning is
derived state. It lives separately under `.harnery/semantic/v2/` and never writes
back to the canonical ledger.

Every claim carries the event IDs that support it. Invalid output, an unavailable
model, and a rate-limited request produce typed receipts instead of silently
keeping old meaning.

## Model routing

The source harness determines the reader. Harnery does not fall back to a model
from another harness.

| Source harness | Configured reader |
| --- | --- |
| Claude Code | Haiku 4.5 |
| Codex | GPT-5.6 Luna |
| Cursor | Composer 2.5 |

The adapters request those exact models. When a harness does not attest the
executed model in its result envelope, the stored reader records
`model_attestation: "requested-only"` rather than claiming that the model was
verified.

## Subcommands

```bash
harn semantic once                         # run one bounded pass
harn semantic once --calls-per-hour 12     # use a lower local ceiling
harn semantic service start                # opt in to recurring model calls
harn semantic service status               # inspect liveness and bounded metrics
harn semantic service stop                 # finish the current call, then stop
harn semantic doctor                       # check readers without a model call
harn semantic inspect <instance-or-generation>
```

`once` is the only command here that spends model calls. It projects safe evidence
from active V3 generations, schedules the oldest eligible work, reuses an exact
input cache, validates citations and privacy boundaries, and atomically publishes
the resulting agent document.

The hard ceiling is 60 calls per coordination root in any rolling hour. A lower
`--calls-per-hour` value is allowed. Requests beyond the active ceiling receive a
`deferred` document with an `eligible_after` time.

`doctor` reports which harness binaries are available, the configured model for
each one, and the current semantic manifest. It makes no model request.

`inspect` accepts either an instance ID or generation ID and returns the current
semantic document. Consumers decide whether a document is fresh by comparing its
source cursor to the current V3 projection. Freshness is not stored as a second
authority in the document.

`service start` is an explicit authorization for recurring model calls. It
starts one detached service per coordination root. The service watches the
canonical active-ledger path, debounces changes for five seconds, consumes an
incremental ledger cursor, and keeps at least 30 seconds between calls for one
generation. A stale process lease is recovered by the next explicit start.

Stopping is graceful. An in-flight model request may finish, but no next request
starts. The deterministic ledger, coordination commands, and Codec remain usable
whether the service is stopped, unavailable, or recovering.

## Codec

Codec reads validated agent documents on the server and presents them as a
separate semantic channel. It can fill an otherwise inferred focus bubble and a
neutral expression, but it never replaces event-backed activity, lifecycle,
operation, attention, relationship, or freshness state. Expanded panel detail
labels model synthesis and prediction, shows the reader and attestation, and
removes expired meaning while retaining a typed stale or unavailable receipt.

Version 2 adds an optional `expression_cue`. The reader may choose `focused`,
`curious`, `deliberating`, `investigating`, `building`, `coordinating`,
`planning`, `verifying`, `weighing`, or `wrapping-up`. It may also abstain. A cue
must cite supplied events, use model-synthesis basis, and carry medium or low
confidence. Deterministic expressions such as waits, blockers, errors,
recovery, compaction, observation, context pressure, and open-subagent state
always take precedence.

The scene header reports whether the semantic service is running. Opening Codec
never starts the service and never authorizes model spend. Semantic documents and
service health are local-only; presence relay payloads strip both.

## Storage boundary

All state is disposable and rebuildable:

```text
.harnery/semantic/v2/
├── manifest.json
├── agents/<generation_id>.json
└── cache/<cache_key>.json
```

The cache key includes the evidence digest, source harness, configured and
resolved model IDs, evidence contract version, and prompt contract version.
Changing any of those inputs prevents stale reuse.

Version 1 documents and cache entries are rebuildable derived state. The V2
reader does not migrate or consume them.
